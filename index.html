Optimización de Fixture

Armamos el modelo matemático juntos: elegís las restricciones y el programa encuentra el fixture que minimiza los kilómetros recorridos.

1. Los datos: 10 clubes y sus distancias reales

Estas son las distancias reales (en línea recta) entre los estadios de 10 clubes argentinos. Este dato de entrada ya está armado — el modelo lo va a usar para decidir el fixture.

2. Restricciones del modelo

Cada restricción es una condición que el fixture tiene que cumplir sí o sí (o que decidís agregar). A la derecha de cada una vas a ver cómo se escribe matemáticamente.

Para cada par de equipos i≠j:   Σk (xi,j,k + xj,i,k) = 1

Para cada equipo i y cada fecha k:   Σj≠i (xi,j,k + xj,i,k) = 1

Para cada equipo i:   -1 ≤ Σj,k xi,j,k − Σj,k xj,i,k ≤ 1

Recomendado dejarla activada: sin ella, el modelo puede armar fixtures raros (un equipo de visitante casi siempre) que igual minimizan el objetivo.

Para cada equipo i y cada ventana de 3 fechas consecutivas:   1 ≤ Σj xi,j,k + xi,j,k+1 + xi,j,k+2 ≤ 2

xlocal,visitante,5 = 1

Para cada fecha k:   Σj xriver,j,k + Σj xboca,j,k = 1

Para cada equipo i:   Σj(xi,j,1 + xi,j,2) = 1   y   Σj(xi,j,n-2 + xi,j,n-1) = 1

Si activás muchas restricciones a la vez, puede que no exista ningún fixture que las cumpla todas — el solver te lo va a decir (modelo infactible). Es una lección válida: a veces hay que resignar alguna.

3. Función objetivo

Sumar la distancia total de todos los partidos no sirve como objetivo: como cada par se enfrenta una sola vez y la distancia es simétrica (A–B mide lo mismo que B–A), esa suma es siempre la misma, no importa cómo armes el fixture. Lo que sí varía es cómo se reparte esa distancia entre los equipos.

Minimizar   0

Para cada equipo calculamos su "distancia promedio natural" a los demás (un dato fijo, geográfico). El objetivo es que la distancia que realmente recorre de visitante quede lo más cerca posible de esa distancia promedio multiplicada por la cantidad de partidos que le toque de visitante.
